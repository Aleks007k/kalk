# Калькулятор-тайник — архитектура

Статус: **согласовано, код ещё не начат.**
Целевой телефон: Samsung Galaxy S21 Ultra, One UI 7, Android 15.

## 1. Что делаем

Android-приложение, которое снаружи выглядит и работает как обычный калькулятор.
Если набрать секретный PIN и нажать «=», открывается зашифрованный тайник для фото,
видео, PDF, текстов и заметок. Спрятанные файлы не видны ни в галерее,
ни в файловых менеджерах, ни в других приложениях.

## 2. Решения, принятые на интервью

| Вопрос | Решение | Почему |
|---|---|---|
| Платформа | Только Android | Установка APK бесплатная и простая |
| Резервные копии файлов | **Нет** | Максимальная секретность. Удаление приложения, «Очистить данные», сброс или потеря телефона = файлы потеряны |
| PIN | 8–12 цифр | Короче — профессионал подберёт за дни (§5.1) |
| Забытый PIN | **Код восстановления из 16 цифр на бумаге** | См. §5. Секретные вопросы отклонены: ответы часто знают близкие, а близкие — как раз главная угроза |
| Фальшивый PIN | Да, второй безобидный тайник | Защита, если заставят открыть |
| Объём | Много, включая большие видео (до 8K) | Шифрование кусками, видео без расшифровки на диск |
| Что храним | Фото, видео, PDF, заметки в формате TXT (+ любые другие файлы без просмотра) | §8 |
| Заметки Samsung Notes | Перенос через экспорт в TXT, в тайнике становятся редактируемой заметкой | Свой формат Samsung не читается другими приложениями |
| Копирование текста | Из тайника в любое приложение и обратно | В отличие от «Защищённой папки» Knox, буфер обмена общий |
| Регистрация разработчика Google | Сразу после этапа 1, бесплатно | §12 |
| Оригинал после переноса | Удаляется (через системное подтверждение) | Иначе прятать бессмысленно |
| Маскировка | Значок и название «Калькулятор» | Не выделяется |
| Отпечаток / лицо | Нет, только PIN | Плохо сочетается с фальшивым PIN |
| Доступ в интернет | **Нет совсем** (нет разрешения `INTERNET`) | Приложение физически не может ничего никуда отправить |

## 3. От чего защищаемся, а от чего нет

**Защищает:**
- человек взял разблокированный телефон и листает галерею или файлы;
- кто-то открыл «Калькулятор»: он работает как калькулятор, неверный PIN просто даёт результат вычисления;
- вас заставили открыть тайник: вы вводите фальшивый PIN;
- файлы скопировали с телефона: без PIN и защищённой зоны этого телефона их не расшифровать.

**Не защищает:**
- **копии в облаке.** Автозагрузка Google Фото и синхронизация галереи Samsung с OneDrive: оригинал мог уже уйти туда, удалять вручную;
- **вирус или шпионская программа** на телефоне в момент просмотра;
- **размер данных.** Специалист может увидеть, что приложение занимает, например, 5 ГБ. В фальшивый тайник стоит положить правдоподобное содержимое;
- **человек, который нашёл бумажку с кодом восстановления.** Её надо хранить отдельно от телефона.

Исходный код открыт (репозиторий публичный). Это не ослабляет шифрование: стойкость держится на PIN и ключах, а не на секретности кода.

## 4. Вход

```
Значок «Калькулятор»
   │
   ▼
Калькулятор (работает по-настоящему: + − × ÷ %, ±, десятичные)
   │  нажато «=»
   ▼
Результат показывается СРАЗУ (как в обычном калькуляторе).
Параллельно, в фоне: если введены только цифры —
   ├─ 8–12 цифр  → проверка как PIN по ОБОИМ слотам (всегда оба, время одинаковое)
   │                 ├─ слот A подошёл → открыть тайник A
   │                 ├─ слот B подошёл → открыть тайник B
   │                 └─ ни один        → ничего не происходит
   ├─ 16 цифр    → проверка как код восстановления → «Придумайте новый PIN»
   └─ иное       → ничего
```

- **Первый запуск.** Один раз проходит настройка:
  1. придумать PIN (8–12 цифр) и повторить его;
  2. приложение показывает код восстановления;
  3. код нужно **набрать заново с бумаги**, чтобы ошибка в записи не стоила потери файлов;
  4. тайник создаётся.

  После этого приложение всегда открывается как калькулятор.
- **Правила PIN.** PIN не может начинаться с 0: калькулятор, как любой калькулятор, не даёт набрать ведущий ноль. Не принимаются PIN из одинаковых цифр (`77777777`) и из цифр подряд (`12345678`, `98765432`). Код восстановления тоже никогда не начинается с 0.
- **Фальшивый PIN** задаётся в настройках внутри настоящего тайника.
- **Два слота существуют всегда.** При настройке настоящий тайник **случайно** попадает в слот A или B. Во второй слот кладётся «наполнитель»: полноценный слот со случайным PIN, кодом и своим пустым оглавлением. Поэтому ни по положению, ни по размеру, ни по числу файлов оглавлений не понять, какой слот настоящий и задан ли фальшивый PIN.
- **Проверка обоих слотов идёт параллельно**, и ответ ждёт оба результата. Время ответа не зависит от того, какой слот подошёл.
- **Подбор PIN.** Блокировки после ошибок нет: неверный PIN выглядит как обычное вычисление. Защита — медленная проверка (Argon2id) плюс привязка к защищённой зоне телефона (§5).
- **Прерванная настройка.** Если найден только один слот, настройку прервали. Если в тайнике нет ни одного файла, половинчатый слот удаляется и настройка начинается заново. Если файлы есть, ничего не удаляется.

## 5. Ключи и шифрование

**Библиотека — Google Tink.** Это открытый код (лицензия Apache 2.0), он работает только на телефоне и в сеть не ходит. Ключи создаются на телефоне и никуда не передаются, у Google к ним доступа нет. Своей криптографии не пишем. (`androidx.security:security-crypto` / `EncryptedFile` объявлены устаревшими в 2025 году, их не используем.)

**Ключи одного слота:**

```
Мастер-ключ тайника (случайный, 256 бит) — им шифруются все файлы тайника
   │
   ├─ обёртка №1 (для ежедневного входа):
   │     a = Argon2id(PIN, соль)                      ~0,5 с, 64 МБ
   │     k = HMAC-SHA256 внутри Android Keystore (a)  неизвлекаемый ключ в защищённой
   │                                                  зоне процессора Samsung
   │     k шифрует мастер-ключ (AES-256-GCM)
   │
   └─ обёртка №2 (для восстановления):
         r = Argon2id(код восстановления, соль)       ~2–3 с, 256 МБ
         r шифрует мастер-ключ (AES-256-GCM)          БЕЗ Keystore — см. ниже
```

- **Каждая попытка PIN проходит через Keystore.** Ключ Keystore участвует в вычислении ключа из PIN, а не просто «запирает» готовый результат снаружи. Поэтому, даже вытащив файлы, перебирать PIN на видеокартах нельзя: каждую попытку приходится делать на самом телефоне.
- **Код восстановления — 16 случайных цифр** (около 53 бит) и «тяжёлый» Argon2. Его нельзя подобрать даже без Keystore (оценки в §5.1).
- **Зачем код восстановления не привязан к Keystore.** Это страховка от редких сбоев хранилища ключей после обновлений. Если Keystore сломается, PIN перестанет работать, но код откроет тайник и даст задать новый PIN.
- **Показ кода.** Код показывается один раз при настройке, группами: `4821 0937 5512 6604`. Его нужно записать на бумагу и хранить отдельно от телефона. Вводится в калькулятор + «=». В настройках можно выпустить новый код (старый перестанет работать).
- Фальшивый слот B тоже содержит «обёртку восстановления» из случайных байтов, чтобы слоты выглядели одинаково.
- **Keystore-ключ создаётся без требований к блокировке экрана** (`setUserAuthenticationRequired` не используется), чтобы смена блокировки экрана телефона не уничтожила ключ.
- **Параметры Argon2id** подстраиваются под S21 Ultra на этапе 2. Библиотеку (Bouncy Castle или нативная) выберем и проверим там же.
- Мастер-ключ живёт в памяти, только пока тайник открыт.

### 5.1. Сколько займёт взлом (грубые оценки)

Сценарий: телефон у профессионалов, они **уже обошли блокировку экрана Samsung** (это само по себе трудно на свежих обновлениях) и запускают свой код на телефоне. Скорость перебора — около 5 PIN в секунду.

| Что подбирают | Максимальное время |
|---|---|
| PIN 6 цифр | ~2 дня |
| **PIN 8 цифр (минимум в приложении)** | **~8 месяцев** |
| PIN 10 цифр | ~60 лет |
| Код восстановления, 16 цифр (даже вне телефона, ферма из 1000 видеокарт) | больше 1000 лет |

Поэтому **минимальная длина PIN — 8 цифр**. Для людей, у которых нет профессиональных инструментов, недоступен даже PIN из 6 цифр: они вообще не могут достать данные приложения.

**Содержимое файлов:**
- Tink `StreamingAead`, режим `AES256_GCM_HKDF_1MB`: шифрование кусками по 1 МБ, каждый кусок проверяется на целостность.
- Имена на диске случайные (`a8f3…e1.bin`). Настоящее имя, тип, дата и размер — только в зашифрованном оглавлении.
- Миниатюры — отдельные маленькие зашифрованные файлы.
- Файлы обоих тайников лежат в одной общей папке.

## 6. Хранение на диске

Во внутренней папке приложения (`/data/data/<пакет>/files`), закрытой от других приложений.

```
files/vault/
  slot_A.bin            обёртки мастер-ключа слота A
  slot_B.bin            то же для слота B (настоящий тайник, фальшивый или наполнитель)
  index_<имя>.bin       зашифрованное оглавление каждого тайника;
                        <имя> = HMAC(мастер-ключ), без ключа не понять, чьё оно
  blobs/<random>        зашифрованные файлы, заметки и миниатюры обоих тайников
  tmp/                  незавершённые операции, очищается при каждом запуске
```

- Оглавление хранит для каждого файла имя, тип, размер, даты, отпечаток SHA-256 и исходную папку (формат 3; старые форматы 1 и 2 читаются).
- Вне тайника хранится одна открытая настройка — число колонок сетки (`shared_prefs/ui.xml`). Она общая для настоящего и фальшивого тайника и ничего не говорит о файлах.
- Резервная копия Android **выключена** (`allowBackup=false`, `dataExtractionRules` исключают всё). Иначе данные ушли бы в Google Drive или Samsung Cloud.
- Оглавление и слоты пишутся атомарно: сначала во временный файл, потом мгновенное переименование. Выключение телефона ничего не портит.

## 7. Перенос файла в тайник

1. Зашифровать кусками в `tmp/`, по ходу считая отпечаток SHA-256 прочитанного.
2. **Проверить:** полностью расшифровать результат. Размер и отпечаток должны совпасть с прочитанным. Если известен размер из галереи, он тоже должен совпасть.
3. Если файл с таким же отпечатком уже есть в тайнике, второй раз он не добавляется. Оригинал при этом всё равно можно удалить: копия в тайнике есть.
4. Миниатюра (≈320 px, JPEG) шифруется отдельным файлом.
5. Переместить в `blobs/` и атомарно обновить оглавление.
6. **Только потом** удалить оригиналы: для фото и видео — `MediaStore.createDeleteRequest`, одно системное окно подтверждения на пачку. Для документов — сначала наш вопрос «Удалить оригиналы?», затем `DocumentsContract.deleteDocument` (если источник позволяет; иначе подсказка удалить вручную).

Сбой на любом шаге → оригинал на месте, мусор из `tmp/` удаляется при следующем запуске. Сбой одного файла не останавливает остальные. Если тайник закрыли посреди работы, уже добавленные файлы остаются в тайнике, а оригиналы не удаляются. При повторном добавлении тайник узнает их по отпечатку.

- **Фото и видео** выбираются в собственной сетке на основе `MediaStore`. Нужно разрешение «Фото и видео» — так решил владелец ради удобства. Приложение запрашивает его только изнутри тайника, при первом добавлении. На Android 14+ при частичном доступе («Выбрать фото») видны только разрешённые фото, и есть кнопка «Выбрать другие».
- Системный Photo Picker не подходит: выбранное через него нельзя удалить из галереи.
- **PDF, TXT и прочие файлы** выбираются в системном окне (`ACTION_OPEN_DOCUMENT`). Разрешение для них не нужно.
- **Системные окна** (выбор файлов, подтверждение удаления, запрос разрешения), открытые нашей кнопкой, тайник сразу не запирают. Если не вернуться в приложение за 3 минуты, тайник запирается.
- Пока идёт шифрование, экран не гаснет: иначе блокировка прервала бы длинное видео.
- **Файл хранится байт-в-байт.** При возврате в галерею он идентичен оригиналу: живые фото Samsung (Motion Photo), EXIF, дата и геометка сохраняются.
- **Исходная папка** (например, `DCIM/Camera/`) запоминается в оглавлении, чтобы вернуть файл туда же.
- **Миниатюры** 512 px, чтобы и в две колонки сетка была чёткой (у файлов из версии 0.4.0 — 320 px).
- **Геометка.** Android по умолчанию вырезает место съёмки из фото и видео, которые читает другое приложение. Поэтому вместе с «Фото и видео» запрашивается `ACCESS_MEDIA_LOCATION` (то же окно, отдельного вопроса нет), а файл открывается через `MediaStore.setRequireOriginal`. Если система не дала это разрешение (например, при частичном доступе), файл всё равно добавляется, но уже без геометки.

### 7.1. Возврат файла из тайника

Долгое нажатие на файл → «Восстановить». Работает на Android 10 и новее: туда приложение может положить файл в Галерею без разрешений.

1. Файл создаётся через `MediaStore` скрытым (`IS_PENDING`): фото и видео — в исходную папку, документы — в `Download/`. Если исходная папка недоступна (например, чужая папка приложения), фото идут в `Pictures/`, видео — в `Movies/`, а запасной вариант для всего — `Download/`.
2. Файл расшифровывается в него, по ходу считается SHA-256. Размер и отпечаток должны совпасть с записанными при добавлении.
3. Записанный файл перечитывается с диска, отпечаток сверяется ещё раз.
4. **Только потом** файл становится видимым в Галерее, а из тайника удаляется.

Сбой на любом шаге → недописанный файл стирается, в тайнике всё остаётся как было. Дата съёмки берётся из самого файла (EXIF у фото, данные видео). У файлов без этих данных (например, некоторых скриншотов) в Галерее будет дата возврата.

## 8. Форматы и просмотр

| Тип | Форматы | Просмотр |
|---|---|---|
| Фото | JPEG, PNG, WebP, GIF (с анимацией), HEIC/HEIF, DNG (RAW из режима «Про»), BMP | Внутри, расшифровка в память; увеличение пальцами и двойным нажатием |
| Видео | MP4, MOV, MKV, WebM, 3GP; кодеки H.264, H.265/HEVC, VP9, AV1 — всё, что умеет телефон, включая 8K и HDR10+ с S21 Ultra | Внутри, плеер Media3 с расшифровкой на лету и перемоткой; на диск ничего не пишется |
| PDF | PDF | Внутри, постранично, с увеличением; файл только в памяти (Android 11+), на Android 8–10 — временный файл, стираемый сразу после открытия |
| Заметки | TXT (UTF-8, UTF-16 и Windows-1251 распознаются сами; сохраняется в UTF-8) | Внутри: просмотр и редактирование с автосохранением; новые заметки — кнопкой «+ Заметка» |
| Прочее | Любые файлы | Только хранить и возвращать обратно, без просмотра |

### 8.1. Как устроен просмотр (с версии 0.6.0)

- Нажатие на плитку открывает файл на весь экран. Листание влево-вправо идёт в том же порядке, что и сетка. Если листать дальше последнего (или раньше первого) файла, просмотр закрывается и видна сетка. «⋮» открывает то же меню, что долгое нажатие: «Восстановить» или «Удалить». После этого показывается следующий файл.
- **Фото** расшифровывается целиком в память и раскодируется системой (HEIC, анимация GIF/WebP, поворот по EXIF). Снимки до ~16 Мп показываются в полном разрешении. Огромные (50–108 Мп, панорамы) уменьшаются в 2–4 раза, чтобы не переполнить память. Файлы больше 200 МБ не открываются, их можно восстановить. Увеличение пальцами и двойным нажатием — библиотека Telephoto. Одновременно раскодируются не больше двух фото.
- **Видео** — плеер Media3 (ExoPlayer). Свой источник данных читает зашифрованный файл через канал Tink с произвольным доступом: расшифровываются только нужные куски по 1 МБ, поэтому перемотка в любое место мгновенная. Плеер создаётся только для страницы, на которой остановилось листание, и освобождается при перелистывании или запирании тайника.
- Кадры видео выводятся в `TextureView`: его, в отличие от `SurfaceView`, можно увеличивать пальцами и двойным нажатием, как фото. Окно тайника целиком защищено `FLAG_SECURE`, поэтому кадры не попадают на скриншоты и запись экрана.
- Кнопки плеера свои (Compose): −10 с, пауза/пуск, +10 с, ползунок перемотки и время. Пока видео играет, панели прячутся через 3 секунды; нажатие на видео показывает их снова.
- **На диск ничего не пишется**: ни кадры, ни расшифрованные куски.
- **Сеть запрещена дважды.** В манифесте `INTERNET`, `ACCESS_NETWORK_STATE` и `ACCESS_WIFI_STATE` вычёркнуты (`tools:node="remove"`), даже если их попросит библиотека. Сборка на GitHub проверяет готовый APK (`aapt2 dump permissions`) и останавливается, если сетевое разрешение всё же появилось.

### 8.2. PDF и заметки (с версии 0.7.0)

- **PDF.** Страницы листаются вверх-вниз (влево-вправо — другие файлы), каждую можно увеличить пальцами и двойным нажатием; внизу — номер страницы. Системному `PdfRenderer` нужен файл, поэтому расшифрованный PDF кладётся в «файл в памяти» (`memfd`, Android 11+) — на диск ничего не попадает. На Android 8–10 PDF на мгновение пишется во внутреннюю папку (`no_backup/doc-tmp`) и стирается сразу после открытия; остатки после сбоя стираются при запуске. PDF с паролем не открывается — его можно восстановить. У новых PDF в сетке миниатюра первой страницы.
- **Заметки.** Просмотр текста и кнопка «Изменить». Редактор сохраняет сам через 0,8 с после последнего нажатия клавиши: тайник запирается при уходе из приложения, и несохранённое пропало бы. Каждое сохранение шифруется и проверяется так же, как добавление файла, и заменяет содержимое записи (старый зашифрованный файл удаляется после записи оглавления). «+ Заметка» создаёт новую; название — первая строка текста. Пустая новая заметка не создаётся.

**Заметки = TXT.** Отдельного формата нет: каждая заметка хранится как зашифрованный TXT-файл. Импортированный TXT сразу становится редактируемой заметкой. «Восстановить» выгружает обычный `.txt` в «Загрузки».

**Перенос из Samsung Notes** (свой формат `.sdocx` другие приложения не читают):
1. В Samsung Notes: заметка → ⋮ → «Сохранить как файл» → «Текстовый файл».
2. В тайнике: «Добавить» → выбрать этот `.txt`. Приложение зашифрует его и удалит экспортированный файл из «Документов».
3. Удалить заметку в Samsung Notes и очистить там «Недавно удалённые». Это делается вручную, приложение не может управлять Samsung Notes.

Форматирование (жирный текст, списки, рукописные записи, картинки внутри заметки) при экспорте в TXT теряется: остаётся только текст.

**Копирование текста** работает в обе стороны: из тайника в любое приложение и обратно, буфер обмена общий (в отличие от «Защищённой папки» Knox).
- Поле ввода заметки просит клавиатуру не запоминать слова (`IME_FLAG_NO_PERSONALIZED_LEARNING`) и не открываться на весь экран.
- Скопированный из тайника текст помечается как секретный (`EXTRA_IS_SENSITIVE`): система не показывает его в превью буфера обмена, вставка работает как обычно.
- **Предупреждение для пользователя:** скопированный текст попадает в историю буфера обмена клавиатуры Samsung, её стоит очищать вручную.

## 9. Защита интерфейса

- Тайник запирается, как только приложение уходит с экрана (домой, в другое приложение, выключение экрана). Ключ при этом затирается нулями. Поворот экрана тайник не запирает.
- Если проверка PIN закончилась, когда пользователь уже ушёл из приложения, тайник не открывается.
- В тайнике и на экранах настройки запрещены скриншоты и запись экрана (`FLAG_SECURE`).
- «Недавние приложения»: если уйти из калькулятора, там видна картинка калькулятора. Если уйти из тайника, снимок не сохраняется: карточка пустая, содержимого тайника на ней нет.
- Незаконченная настройка (PIN, код восстановления) не сохраняется системой на диск: окно не пересоздаётся при повороте, а секреты не попадают в сохраняемое состояние.
- Долгие операции (смена PIN, позже — импорт) работают с копией ключа. Закрытие тайника посреди операции не может испортить данные.
- Нет уведомлений, виджетов, ярлыков и пункта «Поделиться», которые могли бы выдать тайник.
- На экране тайника нет заголовка: со стороны он похож на обычную галерею. Размер плиток меняется щипком двумя пальцами (2–6 колонок), как в Галерее Samsung.
- Два раздела (с версии 0.7.1), переключатель вверху: **«Фото и видео»** — сетка только с фото и видео, кнопка «+ Фото и видео»; **«Файлы»** — PDF, заметки и прочие документы списком (значок или первая страница PDF, имя, дата, размер), кнопки «+ Файлы» и «+ Заметка». Просмотр листает только внутри своего раздела. «Назад» из «Файлов» возвращает к фото, второй «Назад» запирает тайник.
- Значок — современная адаптивная иконка калькулятора (клавиши «+ − × =») с одноцветным вариантом для «темы значков» Android 13+.

## 11. Ключ подписи приложения

**Что это.** Каждое Android-приложение заверяется цифровой «печатью» разработчика. Android ставит обновление поверх старой версии только при совпадении печати. Это защита от подделок: чужой человек не может выпустить «обновление», которое залезет в ваши данные.

**Почему это важно здесь.** Если печать потерять, новую версию придётся ставить только после удаления старой, а при удалении пропадут все спрятанные файлы.

**Как сделано:**
1. **Пароль придумывает владелец** (только латинские буквы и цифры, от 24 символов) и сам кладёт его в секрет GitHub `SIGNING_PASSWORD`. Ни разработчик, ни чат с ассистентом пароль не видят.
2. **Ключ создаёт GitHub** одноразовым процессом `Create signing key (one-time)`: RSA 4096, PKCS12, зашифрован паролем владельца. Пароль передаётся через переменную окружения и в журналы не попадает. Процесс отказывается работать, если ключ уже существует: повторное создание сломало бы обновления.
3. **Зашифрованный ключ хранится в репозитории** (`signing/release.p12`). Без пароля он бесполезен. Копия ключа — сам репозиторий, копия пароля — у владельца.
4. **Сборка проверяет подпись.** Перед выпуском релиза CI сравнивает отпечаток сертификата в APK с отпечатком постоянного ключа. Если они не совпадают, релиз не выпускается. Сборки без пароля (локальные, чужие PR) подписываются отладочным ключом и не публикуются.
5. Версия 0.1.0 была подписана временным ключом. Переход на постоянный ключ (0.2.0) требует **одной** переустановки. В приложении ещё нет данных, поэтому ничего не теряется.

**Что может сделать посторонний на GitHub:**
- **Любой человек** может читать код и скачивать APK, но изменить ничего не может: менять публичный репозиторий может только владелец.
- **На GitHub нет ваших файлов, PIN, кода восстановления и данных с телефона.** У приложения нет доступа в интернет, оно никогда не связывается с GitHub, и GitHub не может «дотянуться» до телефона.
- **Удаление репозитория** не сломает установленное приложение. GitHub нужен только для сборки обновлений.
- **Если кто-то взломает ваш аккаунт GitHub,** он сможет собрать поддельное «обновление». Но установить его на телефон можно только вручную, держа в руках разблокированный телефон. Защита: двухфакторный вход в GitHub и правило «ставлю обновления только по ссылке из этого репозитория, когда сам их заказал».

## 12. Сборка и установка

**Сборка.** GitHub Actions на каждый push прогоняет тесты и собирает APK (кладёт его в Artifacts запуска), а по тегу версии `v*` публикует `Calculator.apk` в разделе Releases. Компьютер и Android Studio не нужны. **Расходы: 0** (для публичных репозиториев сборка бесплатная без лимитов).

**Имя пакета:** `com.pocketcalc.calculator` (неизменно; менять нельзя — это сломало бы обновления). Сжатие кода (R8) на этапе 1 выключено ради надёжной первой сборки, включим на этапе 2.

**Первая установка на S21 Ultra (One UI 7):**
1. *Настройки → Безопасность и конфиденциальность → Автоблокировщик* → выключить. Samsung по умолчанию блокирует установку не из магазинов. Включить обратно можно сразу после установки.
2. Открыть в Chrome ссылку на последний релиз → скачать `Calculator.apk` → нажать на загруженный файл.
3. Chrome спросит «Разрешить установку из этого источника?» → разрешить → «Установить».
4. Если появится окно Play Protect «Неизвестный разработчик» → «Подробнее» → «Всё равно установить».

**Обновление:** скачать новый APK и установить поверх (шаги 1–2–4). Данные сохраняются. Внутри приложения проверки обновлений нет, потому что у него нет доступа в интернет.

**Проверка разработчиков Google.** С 30.09.2026 она обязательна в Бразилии, Индонезии, Сингапуре и Таиланде; глобально — с 2027 года. После введения уже установленные приложения продолжают работать, но **устанавливать и обновлять** можно только зарегистрированные.

**Решение: регистрируемся сразу после этапа 1.** К этому моменту имя пакета и ключ подписи уже созданы и больше не меняются.
- Это бесплатно и занимает около 15 минут: «аккаунт для ограниченного распространения», только email, без документов, до 20 устройств, телефон привязывается по QR-коду.
- Ждать до 2027 года смысла нет: в момент введения правил можно остаться без обновлений.
- **Цена:** Google узнает, что ваш email зарегистрировал приложение с нейтральным именем пакета. О содержимом тайника Google не узнает ничего.

```
app/src/main/java/.../
  calculator/   калькулятор: разбор выражения, экран
  auth/         первый запуск, PIN, код восстановления, слоты, Argon2, Keystore
  vault/        мастер-ключ, оглавление, хранилище blobs, атомарная запись

  viewer/       фото, видео (Media3 DataSource), PDF

  settings/     смена PIN, фальшивый PIN, новый код восстановления
signing/        release.p12 (зашифрован паролем)
.github/workflows/  сборка APK и релиз
```

## 14. План работ

1. **Каркас.** Проект, рабочий калькулятор, ключ подписи, сборка APK в GitHub Actions. Ставим на телефон, проверяем установку, регистрируем приложение в Google (§12).
2. **Ядро шифрования + автотесты.** Слоты, обе обёртки, шифрование файлов, оглавление. Тесты: верный и неверный PIN, код восстановления, «сломанный Keystore», повреждённый файл, оборванная запись, файл 4+ ГБ.
3. **Вход.** Первый запуск, PIN и код через «=», два слота, автоблокировка.
4. **Импорт.** Фото и видео из галереи, файлы, проверка, удаление оригиналов.
5. **Просмотр.** Сетка миниатюр, фото, видео, PDF, заметки (TXT) с редактированием.
6. **Управление.** Смена PIN, фальшивый PIN, новый код восстановления. (Возврат в галерею и удаление сделаны раньше, в версии 0.5.0.)
7. **Укрепление и проверка на S21 Ultra** (§15).
